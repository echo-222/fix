# 任意内容 → 3D 交互讲解（自由生成）

上传的资料不是说明书、折纸、立体书、物理原理、机械结构时，用这份 skill：烹饪、手工、绳结、化学 / 生物实验、运动与急救、软件操作、科普、流程规则……分流拿不准的资料也走这里。
产物和别的链路一样是一份 `ManualSpec`（纯 JSON），用同一套编译器、渲染器和审计。场景脚本的写法见 [manual-to-3d 的 reference.md](../manual-to-3d/reference.md) 和 [craft.md](../manual-to-3d/craft.md)；题材配方、造型速查、动作技巧见 [reference.md](reference.md)。

## 网站要的成品

「懂了 Dongle」里的一份 3D 交互演示是这样被看的，脚本要为它服务：
- **首页卡片**：`name`（≤ 16 字：主题 + 钩子，例如「手冲咖啡：一杯的 4 个阶段」）、`desc`（≤ 30 字，一句话讲看完能学会什么）、`category`（品类，决定首页归到哪个大类）。卡片上是 3D 模型的样子，取第一个指南的成品状态。
- **打开后**：一个 3D 场景（线稿 / 写实可切换，能 360° 转），左边是指南和步骤列表；点一步，场景播一次「上一步 → 这一步」的过渡动画，再循环播这一步的动作；画面上有高亮、标注、细节窗；顶栏显示尺寸 `dims`；「材料与要点」面板显示 `package`（材料 / 工具）和 `params`（要点、数字、公式）。
- **手机上也要看得清**：标注少而短，镜头不要太远。

所以：场景要有一眼能认出的实物；每一步都要有看得见的变化；文字短、数字准。

## 那条真正重要的原则

**演出来，不是画出来。** 不画流程图、箭头图、文字卡片；找到内容背后的**实物**（锅、试管、人偶、手机、绳子、地球仪……），让实物的状态变化把内容讲出来：放进去、转过去、亮起来、出现、消失、来回动、屏幕换页。
抽象的东西也要找载体：「热传导」是一根被加热的金属棒上的颜色依次变化；「App 注册流程」是一部手机上的界面一页页切换；「心肺复苏」是一个人偶和一双按压的手。

## 工作流

```
- [ ] 0 读懂：主题、受众、终点（看完能做到 / 明白什么），原文的顺序和数字
- [ ] 1 讲解提纲：3–6 个关键时刻 → 指南和步骤
- [ ] 2 选形态：genre、category、指南结构
- [ ] 3 搭舞台：实物载体、零件清单（≤ 50）、坐标和尺度
- [ ] 4 写状态：每步一个看得见的变化（reference.md「动作技巧」）
- [ ] 5 镜头、高亮、标注、细节窗
- [ ] 6 文案：标题、说明、要点、数字
- [ ] 7 输出前自检（本文末「复核清单」）
```

### 0. 读懂

先回答四个问题，写进 `notes`：
1. 这份资料教 / 讲的是什么（一句话）？
2. 给谁看（新手、学生、家长、专业人员）？决定用词和细节程度。
3. 看完的人能做到什么、明白什么（终点）？最后一步就演这个。
4. 原文的顺序、数字（时间、温度、比例、次数、尺寸）是什么？数字照抄，没写的按常识推断并标「推断」。

### 1. 讲解提纲

把内容拆成 3–6 个「关键时刻」（一眼就能看出区别的状态），每个关键时刻 1–4 步。提纲决定指南：
- 「跟着做」的内容（做菜、手工、实验、急救、软件操作）→ 一个按顺序的指南，一个动作一步。
- 「看懂」的内容（科普、原理、流程）→ 一个从整体到局部的指南：总览 → 逐个部分 → 总结。
- 有常见错误 / 注意事项 → 再加一个短指南（3–5 步），每步演一个错误和改正。
总步数 8–30。一步只讲一件事；原文一句话里有两个动作就拆两步。

### 2. 选形态

- `genre`：讲某个具体产品（有品牌型号）怎么用 → `"manual"`；其余一律 `"tutorial"`（面板显示「材料与要点 · 参考资料」）。
- `category`：优先用网站已有的品类（提示词里会给出当前列表）；都不合适就写一个 2–4 字的中文名词（「烹饪」「手工」「化学实验」「运动健康」「急救」「软件操作」「天文地理」），首页会按关键词归大类，归不进去的放「其他」。
- 指南 `kind`：`assembly` = 跟着做的步骤（制作、操作流程）；`usage` = 看懂 / 观察 / 用法；`repair` = 常见错误、故障、注意事项。
- `package`：材料、工具、食材（数量和规格）；`params`：关键数字、比例、时间、公式、安全要点。

### 3. 搭舞台

- **找载体**：按 reference.md「题材配方」选舞台和道具。场景里只放讲这件事必需的实物，道具建到能认出来即可。
- **尺度真实**：毫米，Y 向上，地面 / 桌面 y = 0，观众在 +Z。锅直径 240、试管 Ø16 × 150、人偶身高 1700、手机 72 × 150。`stageSize` 按场景大小给（桌面 600–1200，房间 3000–5000）。
- **认得出**：用合适的形体（reference.md「造型速查」）：球 = 倒满角的 box，锥 = r2 为 0 的 cylinder，人偶 = 一串挂接的 cylinder / box，液体 = 带颜色材质的矮 cylinder。给主要零件写 `finish`（真实材质 / 颜色），写实模式下才像。
- **层级**：会一起动的零件挂成父子（手里拿着的工具挂在手上、杯子里的液体挂在杯子上）；会转的零件原点放在转轴上（关节、铰链、轮轴）。
- 零件 ≤ 50；看不清 / 原文没讲的位置按常识布局，写进 `notes` 的推断里。

### 4. 写状态

每一步至少有一个**看得见的变化**（或者新的高亮 / 标注 / 镜头），能用的手段：

| 想表达 | 写法 |
|---|---|
| 放入、取出、移动、倒、递 | 状态 `at` / `rot`（`lift` 抛物线抬起、`via` 绕开障碍），换父级 `parent` 表示「被拿走 / 放进去」 |
| 打开、翻转、弯曲关节 | `rot` + `arc`（绕铰链 / 关节转），原点在转轴上 |
| 出现、消失、变成另一个样子 | `visible`（两份不同的零件，同一步一个出现一个消失 = 「变化」） |
| 来回动、搅拌、按压、振动、转 | 动作 `slide` / `swing` / `spin` / `press` / `shake` |
| 亮起、闪烁、指示 | `led` + `light: on / blink`、`color` |
| 屏幕上的操作 | `screen` + `ui`（标题、列表、选中项、按钮、提示） |
| 计时、温度、次数 | chips（「中火 3 分钟」「100–120 次 / 分」） |

做不了的：形变（面团揉开、布料、绳子打结的连续过程）、流体、粒子、表情。用「换件」（几个关键形状依次 `visible` 切换）和「代表物」（一排小球表示水流 / 电流）简化，并在 tip 或 notes 里说明。详见 reference.md「动作技巧」。

### 5. 镜头、高亮、标注

- 第 1 步总览全场（`orbit: true`），之后镜头跟着这一步动的东西走；最后一步回到能看全成品的角度。
- `highlight`：这一步动的 / 要看的零件（有移动就要有高亮）。
- `callouts` ≤ 4 个，文字 ≤ 8 字（名称或读数）；小于 15 mm 的东西配 `zoom` 细节窗，`caption` 写结论。
- 镜头 `dist`：手掌大小的东西 250–450，桌面场景 700–1200，人和房间 2500–4500；`dir` 从斜前上方（`[0.4, 0.5, 1]`），不要正上方俯视（除非就是看顶面）。

### 6. 文案

- `title`：动词开头，≤ 14 字（「注水到 250 ml」「双手交叠按压胸口」）。
- `desc`：1–3 句、≤ 80 字，讲做什么 + 对齐到哪 / 做到什么程度 + 为什么；数字照抄原文。
- `tip`：最容易错的地方或安全提醒（有就写，一句话）。
- `chips`：≤ 3 个，放这一步的数字（时间、温度、比例、角度）。
- 简体中文，口语、具体，不写「如图所示」「接下来我们」这类空话。

### 7. 自检

输出前对照本文末的「复核清单」逐项过一遍；对不上的改了再输出。

## 能力边界

| 引擎做不到 | 改成 |
|---|---|
| 物体变形、拉伸、揉捏 | 几个关键形状的零件依次 `visible` 切换 |
| 液体流动、倒水的水柱 | 杯子倾倒（`rot` + `arc`）+ 目标容器里换一份更高的液体；水柱用细 cylinder 出现一下 |
| 烟、火、气泡、粒子 | 几个小零件（火苗 = 橙色锥、气泡 = 小球）`slide` / `swing` 循环，相位错开 |
| 绳子打结、布料 | 绳子用 `cable`（两端挂零件，自动下垂）或一串短 cylinder；打结按关键形状切换 |
| 人物表情、手指精细动作 | 人偶到手掌为止，动作靠手臂关节；手势用 callout 说明 |
| 真实照片、视频 | 不需要：用 3D 实物演；原页在「原说明书」面板里可以对照 |

## 转写要点（网站导入）

这是一份「其他」类资料（不是产品说明书 / 折纸 / 立体书 / 物理原理 / 机械结构，或者分流拿不准）。rows 一条 = 原文的一个步骤、一个要点或一个状态（做菜的一步、实验的一个操作、流程的一个环节、科普的一个知识点），text 照抄关键句和数字，change 写成「场景里什么实物发生了什么变化」（例如「锅里加水到 2/3」「试管里溶液由无色变红」「手机进入注册页」）。entities 写出能当载体的实物（器具、材料、人、设备、界面）和尺寸。另外加一个字段
"plan": { "topic": "一句话主题", "audience": "给谁看", "goal": "看完能做到 / 明白什么", "genre": "manual | tutorial", "category": "建议的品类（2–4 字中文）", "stage": "用什么场景和实物来演（例如：厨房台面 + 炖锅 + 食材）", "moments": ["3–6 个关键时刻"], "unsupported": ["引擎做不了的部分，打算怎么简化"] }。

## 复核清单

- [ ] 一眼认得出场景和主角实物（不是一堆方块）；尺度真实，摆在地面 / 桌面上，没有悬空乱飘
- [ ] 每一步都有看得见的变化，和标题说的一致；没有「空步」或莫名其妙的中间姿态
- [ ] 顺序和原文一致，数字（时间、温度、比例、次数）照抄或标了推断
- [ ] 每步高亮这一步动的东西，镜头看得到它；标注 ≤ 4 个、不挡画面
- [ ] 第 1 步是总览，最后一步是成品 / 结论
- [ ] 做不了的部分有合理的简化，并在 tip 或 notes 里说明
- [ ] name / desc / category / genre 符合网站要求，package、params 填了
- [ ] 文字是简体中文，标题动词开头，没有空话

## 网站后台

网页导入的分流步骤判为「其他」（`free`），或拿不准时，用这份 skill：转写（上面的转写要点）→ 写 ManualSpec JSON（本文 + reference.md + 场景脚本参考 + 两份不同风格的样板）→ 编译 + 审计 + 修复 → 保存 → 截图复核（上面的复核清单）。用户勾了「真实外观」且场景里有合适的实物时，也会走 Tripo 外观模型。提示词由 `server/manualSkill.ts` 每次现读本文件拼成，改这里就能调整自由生成的效果。
